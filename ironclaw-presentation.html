Agent core

The agentic loop

  1. Inbound message

    Channel delivers an IncomingMessage via a merged stream.

  2. Safety gate

    Prompt injection scan, validation, policy check.

  3. Dispatcher to LLM

    Context assembly, tool schemas, provider routing.

  4. Tool execution

    Approval gate, sandbox, execute, leak scan.

  5. Response delivery

    Outbound hooks, channel, user. The loop continues until the turn is done.

Channels

The Channel trait

pub trait Channel: Send + Sync {
    fn name(&self) -> &str;
    fn start(&self) -> Pin<Box<dyn Stream<IncomingMessage>>>;
    fn respond(&self, msg: OutgoingResponse) -> Result<()>;
    fn send_status(&self, status: AgentStatus);
    fn update_secrets(&self, secrets: SecretMap);
}

ChannelManager merges every channel stream into one async stream. A new channel means implementing the trait, adding config and wiring it in app.rs.

Safety

Defense in depth

  1. Prompt injection detection

    Pattern matching and heuristic scanning on all inbound messages.

  2. Input validation

    Schema enforcement, size limits, content filtering.

  3. Policy enforcement

    Per-tool approval gates, capability ceilings.

  4. Leak detection

    Outbound responses scanned for secret material.

Extracted crate

ironclaw_safety lives in crates/ for reuse, re-exported through the src/safety/ shim for backward compatibility.

// Safety is the first and last gate
use ironclaw_safety::SafetyLayer;

// Inbound: scan before the agent sees it
safety.validate_input(&msg)?;

// Outbound: scan before the user sees it
safety.scan_response(&resp)?;

Persistence

Dual-backend database

Oracle AI Database

Primary backend. VECTOR_EMBEDDING(), VECTOR_DISTANCE(), ACID transactions, connection pooling.

libSQL / Turso

Lightweight fallback. FTS5 plus vector search via libsql_vector_idx. Edge-compatible.

Both backends implement the same seven sub-traits. New persistence features must support each one.
